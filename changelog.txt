v0.2.3.3
- Publicized ICheckItemUse interface for crossmod use
- Added CheckItem.RegisterMod for ICheckItemUse with weak references
- Added Lush Wood (from Verdant), vanilla Spooky Wood Trellises
- Added the following Mod.Call functionalities:
	"InOasis": returns bool, takes (Player player)
	Returns if the player is in an oasis.

	"GetOases": returns Rectangle[], takes nothing
	Returns all Oasis bounding boxes in the current world. 

	"RegisterPin": returns CrossmodPin? (a ModItem), takes (Mod mod, string name, string texture)
	Adds a pin from your mod using the given values.

	"RegisterInterest": returns CrossmodInterest?, takes 
		(Mod mod, string name, Func<int[]> getPins, bool isMapped, Func<int, int, HashSet<string>, bool>? mapperFunc, LocalizedText[]? dialogue = null, Func<bool>? isAvailable = null)
	Registers a cross mod "interest". An interest is a rare or semi-rare naturally generated object or structure that can be noted by the Cartographer, alongside using a custom pin.

	"PlaceInterest": returns void, takes (int x, int y, string name) 
	Places the given cross mod interest at the given location. The name should be in the format "MyMod/MyInterest".

- Added the given referenced crossmod support:
	InterestDefinition:
		The backend for an interest definition, used internally for our interests and crossmod interests.
		Refer to our internal definitions for various examples on how to use them: https://github.com/GabeHasWon/SpiritReforged/blob/master/Common/WorldGeneration/PointOfInterest/LegacyInterests.cs

	PinItem:
		The backend for a pin item. Unlike InterestDefinition, CrossmodPin is not necessary for referenced crossmod; simply use the Pinitem class and it will work out of the box.
